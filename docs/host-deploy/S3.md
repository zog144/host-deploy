# Shared S3 storage (0.7.0)

The default bucket is `zog-host-deploy-1`. Each independently initialized workspace
uses its UUID as an object prefix. This prevents accidental name collisions;
workspaces using the same IAM credentials are not security boundaries.
Credentials remain separate from this package.

```sh
host-deploy storage-attach --workspace ./build-workspace
host-deploy job-submit --workspace ./build-workspace --job compile-one \
  --source ./source.zip --recipe ./recipe.json --transfer s3
host-deploy job-collect --workspace ./build-workspace --job compile-one \
  --output ./compile-one.tar.gz --transfer s3
host-deploy storage-results --workspace ./build-workspace
host-deploy storage-fetch --workspace ./build-workspace \
  --id JOB_OR_WORKFLOW_UUID --output ./recovered.tar.gz
```

Attachment happens automatically on first S3 use if storage.json is absent.
An existing storage binding is preserved; use a new workspace if its old storage
creation was denied or its bucket was deleted. SSM remains the default transport;
select `--transfer s3` for both source submission and result collection. Reboot
submission and collection accept the same option.

Collection uploads results and verifies downloaded bytes against the host's
SHA-256 and size before committing a receipt. Only receipt-backed results appear
in storage-results. Storage-fetch validates the receipt's workspace/key binding,
verifies SHA-256 and size, and publishes the local output without overwriting an
existing file. It makes no EC2 or SSM calls: recovery works after host termination.
Keep the workspace or its exported checkpoint to retain the prefix identity.
Recollection can replace a workflow's result as its evidence changes; this is
latest-result storage, not immutable historical versioning. Invalid or incomplete
uploads fail verification rather than being returned as successful evidence.

The controller must perform collection while the host still exists. This pass
does not add automatic unattended S3 publication to the worker. Existing automatic
filesystem publication is separate. Retry collection without rerunning the job.
S3 transfers restart after interruption; durable multipart resume is not added.
Sources are limited to 1 GiB (4 GiB expanded), with a five-minute HTTP transfer
budget. SSM remains available for small transfers.

The VM receives object-scoped URLs valid for up to 15 minutes. These bearer URLs
appear in SSM command history; AWS keys are not installed on the VM. See
[AWS presigned URL documentation](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).

The package does not change this shared bucket's policies, encryption, tags or
lifecycle. Existing administrator rules govern retention. No automatic expiry is
installed. `storage-delete --workspace ...` removes only that workspace prefix,
marks its binding deleted, and keeps the shared bucket. Do this only after all
transfers finish and evidence is no longer needed. In versioned buckets, older
versions can remain billable; this command does not purge historical versions.

Caller permissions required: bucket listing/head access and GetObject, PutObject,
DeleteObject for the workspace prefix; multipart uploads can additionally need
AbortMultipartUpload. KMS-encrypted buckets can require KMS permissions. No
CreateBucket, bucket tagging or bucket-policy permissions are needed for this
shared-bucket path. The old storage-create command is retained only for explicit
creation of dedicated per-workspace buckets and retains its old permissions and
one-day lifecycle behavior. Its storage-delete also deletes that dedicated bucket.

## Public source default

The retained default bucket name `zog-host-deploy-1` is intentional and approved
for this public source. The name is not a credential or a grant of bucket access.
Other deployments must configure a bucket they control and authorize their own
AWS identities. This source does not provision access to the default bucket.
