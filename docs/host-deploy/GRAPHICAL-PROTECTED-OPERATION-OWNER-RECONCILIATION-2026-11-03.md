## Important incompatibilities / acceptance blockers

1. **Different schema, not interchangeable:** PR #21 imports PR #28's `graphical_send_fence_contract.SendOwner`, with `scope` + `claim` and raw 64-hex hashes, while PR #29 expects `graphical_operation_owner_source`'s single strict request, `sha256:` digests, task allowlist, and independent preapproved operation ID -> full frozen request digest. PR #21's CI does *not* exercise PR #29. Do not silently change the pin and assume interoperability.
2. **PR #28's claim receipt is not execution:** PR #28 performs protected `claim_once` but does not own or select the SSM sender. If the gateway retains SSM credentials and uses the claim receipt as a send ticket, another gateway path can bypass the fence. PR #29's `submit_once` owner-selected sender is the safer selected boundary, but its injected `test_sender` is only a synthetic fixture and must never become an RPC argument.
3. **PR #29 currently omits PR #28's explicit verified short-lived operator send/revoke approval** in its synthetic `submit_once`/`revoke` API; its `approval_sha256` is only a field in the protected scope unless authenticated against an independently installed original approval. Add verified approval provenance, single-action purpose, expiry/revocation, immutable original Host/installation/STATE, current operator pin, registry/controller/fingerprint as appropriate, and a distinct no-replacement issuer pin. Keep signing-key rotation checkpoint different from per-operation highwater.
4. **PR #28 currently accepts a fresh signed claim for a new operation ID**, conditional on the signature. For source-history substitution defense, require an independently authenticated *preapproved* original operation ID -> canonical full request digest (PR #29). No gateway-local first-seen enrollment, new guessed operation ID, or reconstructed original approval.
5. **Actual bypass remains:** `src/zog/host_deploy/gateway/generic_pipeline.py` `advance`, currently around lines 384-387, executes `send_intent.claim(...)` followed by `host.submit_command(script,...)`. The local `send_intent` is useful only against journal-only rollback. On any installation where protected owner is required, the gateway must lack the IAM/SSM SendCommand ability; this path MUST fail closed, and the protected native owner alone selects and executes SSM after its irrevocable independent claim. Do not add a gateway flag with insecure fallback. Audit all other SSM send entry points/cancellation and recovery paths, and prevent direct credential reuse.
6. **Linearization and revocation:** independent durable commit of `CLAIMED_UNCERTAIN` before any external send, with one serialized monotonic authority for competing claims and revocation. Post-revocation sends denied. A send started before committed revocation can remain outstanding; revocation does not retroactively cancel. Lost ACK, crash after claim, missing/ambiguous CommandId, recovery, or whole gateway rollback = read-only inspection/HOLD, never resubmit or release claim.
7. **Signed observation is read-only:** fresh nonce, current independently pinned public key, exact original request, external highwater and current epoch; no signed observation grants or transfers SendCommand ability. An unknown operation is not authority to create it.

## Required combined source interface

The protected owner receives a complete, canonical, strictly validated original request that independently binds: Host ID/fingerprint, installation ID, actual STATE volume ID, registry/controller/current authority epoch and pin, lane, immutable reviewed task, catalogue hash, image-build source commit, monthly pin, base generation, predecessor receipt, frozen request ID + original request digest, original root stage-once receipt, operation ID, stage/ordinal, exact remote request digest, immutable AWS target/region/runner selection, and independently signed authorization. The issuer independently verifies *all* source/Host/STATE/authorization evidence and its preapproved original operation mapping; no field becomes authoritative simply because host-deploy supplied it.

An authenticated root-controlled, installed, non-rollbackable ledger transaction atomically retains the unique original claim and serializes revocation. Only the installed owner's fixed trusted sender may call SendCommand; no test sender, arbitrary script, caller-selected SSM endpoint/credentials, temporary alternate direct route, or local gateway bypass. Owner observation is read-only, with exact original CommandId reconciled against trusted SSM/worker history; uncertain outcomes never create a second send.
